## Layer dependency rules

Dependencies point downward only:

```
app → routes → pages → layouts → components → core / styles
                 │         │
                 └─────────┴──→ hooks → services → core
                           └──→ store → core
```

- `components`: pure UI, controlled by props; imports only `@core` utils and `@styles`; never `@hooks`, `@store`, `@services`, `@pages`, `@layouts`, `@tanstack/*`.
- `services` / `store` / `core`: no React UI; never import `@components`, `@pages`, `@layouts`, `@hooks`.
- Cross-layer imports go through the layer barrel (e.g. `@components`). A deep alias (`@components/Icon`) is only used inside the same layer. No `../` imports (the sole exception is `app/router.ts` importing the generated `../routeTree.gen`, which lives outside every layer).

## Aliases

`@app`, `@assets`, `@components`, `@core`, `@hooks`, `@layouts`, `@pages`, `@services`, `@store`, `@styles` — configured in `tsconfig.app.json` and `vite.config.ts` for every allowed layer, even ones with no folder yet.

## Barrels

Every layer folder (except `styles` and `assets`, imported by file) has an `index.ts` re-exporting its public API. Add new units to the nearest barrel in the same change that creates them.
